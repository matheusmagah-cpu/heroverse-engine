## Recommended fixes

- S6: make the long's requirement not depend on a key nothing writes (e.g. pilots from pilot-015, or `package_pilot.py`
  writing `series` and `thumb_episode` for a Bible-story long), with a test on a real package.
- S5: `publish_problems` and `approve` refuse when `spec["episode"] != episode`; validate `episode` with the
  `EPISODE_ID` pattern.
- S4: at publish, require the approved candidate's record to exist with the same sha256 and an R16 PASS, and
  `approved.score >= FLOOR`; add a hookify rule or CI test against hand-edited `thumbs/*.json` approvals.
- S7: contain `repo_path` to `THUMBS`.

## Applied in this PR (E121)

S4, S5, S6 and S7 fixed in commit 1aedc4e6 on the branch, with tests in `bible/test_thumbs.py`
(`test_an_approval_written_by_hand_is_refused`, `test_an_approved_spec_is_not_another_episodes`,
`test_an_episode_name_is_never_a_path`, `test_a_story_long_needs_it_without_a_series_key`), each failing before the fix:
publish re-checks score, note and the recorded candidate (sha256, spec digest, R16 PASS) and that the spec is the
episode's; the approved image is always `bible/thumbs/<episode>.jpg`; an episode name is never a path; a Bible long is
also recognised by its pilot's `script.json` archetype. No hookify rule on `thumbs/*.json`: draft specs are written by
hand by design, so the publish-time re-check is the guard.
