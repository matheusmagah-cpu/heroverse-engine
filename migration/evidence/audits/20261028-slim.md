## 5. Orchestration overlaps and rework risk

Clocks today: GitHub cron `heartbeat.yml` (:41 hourly), GitHub cron `tiktok.yml` (:07, :27, :47), heroverse-runner
`render.yml` (:13, :43), Claude **light clock** (:14 hourly, Haiku, fresh session), Claude **main clock** (:14 every 4 h,
main session), Claude **daily analysis** (08:05 UTC), Claude **daily mining** (09:47 UTC), plus one-shot reminders.

| # | Overlap | Effect | Proposal |
|---|---|---|---|
| O1 | TikTok is checked by four triggers: heartbeat task (hourly :40 slot), `tiktok.yml`'s own cron (3 an hour), light clock step 3, main clock step 9 | Up to 5 pending checks an hour; duplicate dispatches are harmless only because the ledger is idempotent | Heartbeat only; drop tiktok.yml's cron once heartbeat's hourly beat has held for 7 days (its run history says whether GitHub drops it); clocks only alert on a failed run |
| O2 | Heartbeat liveness is checked by both Claude clocks (light step 2, main step 00) and they fire at the same minute (:14) every 4 h | Two sessions read the same state at 00:14, 04:14 ... | Light clock only; move the main clock off :14 (e.g. :29) or let it skip what the light clock owns |
| O3 | Main clock steps 0 and 1 (Claude review of `render_queue preview-review/review`, images → `cf-images.yml`) | Both queues read prayer pilots only; empty since 2026-10-26 | Keep them as one line ("if render_queue lists anything") until a story long goes through `pilot-NNN` |
| O4 | Live-intelligence daily loop runs "in the first main clock after 16:00", the daily analysis at 08:05 reads the same `evidence/learning/`, and goal-report at 07:45 computes the funnel | Three places compute or read one daily verdict | One daily job: goal-report 07:45 (data) → daily analysis 08:05 (verdict, decision, live-intel hypothesis) → mining 09:47 (vidIQ, same ≤ 10 calls/day budget shared and recorded first) |
| O5 | `channel-privacy.yml` daily plan | Repeats a finished job daily | Remove the heartbeat slot (DECIDE) |
| O6 | Rework points: `reconcile.yml` re-dispatches `approve.yml`/`publish.yml`/`publish-episode.yml` from `render_queue reconcile`; `dispatch_guard.py` refuses a rerun on a failed subject without a new commit (E116), and `publish-episode.yml`/`first-comment.yml` are idempotent by ledger | Guarded | KEEP; the only unguarded re-run is the Claude clocks dispatching `tiktok.yml` by hand (O1) |

**Proposed single-clock design.** One scheduler of record (`heartbeat.yml`, as now: the only cron per
`test_schedules`), one watchdog (the light clock, Haiku: re-dispatch heartbeat when > 55 min stale, report failed runs
and missed slots to the main session, nothing else), and one daily Claude pass (08:05: report → decision → live intel;
mining at 09:47 under the same vidIQ budget). The 4-hourly main clock keeps only production work (long and Shorts
pipeline, reviews, PRs) and stops re-checking heartbeat and TikTok. `tiktok.yml`'s cron goes after 7 clean days of the
heartbeat; `channel-privacy.yml` leaves the heartbeat.
