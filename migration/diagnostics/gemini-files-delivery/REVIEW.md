# Gemini Files API: one-file delivery proof

Status: prepared and tested offline, not committed, not dispatched, no Gemini API call made by this preparation.

## Narrow outcome

Deliver exactly one synthetic `c01.mp4` to the existing Gemini Files API, observe `ACTIVE`, and compare the provider's SHA-256, byte count, MIME type and duration to the exact runner-generated file. This is a delivery/processing proof only. It does not establish audio ingestion by a model, synchronization accuracy, semantic understanding, forecast quality or production readiness.

The nominal control is sound **500 ms after** each flash. Local decoded measurements in the preparation environment were +0.500, +0.501, +0.501 seconds. Positive means audio late. The provider receives only the MP4 bytes and neutral display name `c01.mp4`, never the generator, expected answers, manifests, measurements or prompt.

## Official basis and cost boundary

Sources checked 2026-10-16:

- [Files API usage](https://ai.google.dev/gemini-api/docs/files#usage-information): Files is available at no cost; maximum 2 GB per file, 20 GB per project, 48-hour storage. This proof caps its single MP4 at 262,144 bytes and does not change billing. Automatic provider expiration is expected; it makes no delete request.
- [File resource and states](https://ai.google.dev/api/files#File): `sha256Hash` encodes SHA-256 bytes in base64; `sizeBytes`, `mimeType`, `videoMetadata.videoDuration`, `state` and `uri` are output fields. `ACTIVE` means processing completed and the file is available to a later inference request. It is not a model's observation of the audio or visual stream.
- [Upload](https://ai.google.dev/api/files#method:-media.upload) and [Files guide](https://ai.google.dev/gemini-api/docs/files): use the resumable start/finalize protocol and metadata GET.
- [Token reference](https://ai.google.dev/api/tokens) describes the tokenizer endpoint but does not explicitly state its price. [Billing FAQ](https://ai.google.dev/gemini-api/docs/billing#is-gettokens-billed) names `GetTokens`, not the exact REST `countTokens` endpoint. This preparation deliberately does not infer that the names are interchangeable. **countTokens is absent from the executable allowlist and workflow.**

Files' documented no-cost status covers this restricted operation regardless of a generation model's paid/free tier. Secret presence alone proves neither validity nor project identity nor free inference eligibility. The proof does not query or modify billing, create credentials, request OAuth access, use an SDK fallback or expose the key. GitHub Actions runner usage is a separate account-budget check owned by the parent before any future dispatch.

## Exact HTTP requests

All authentication is the existing `HERO_GEMINI_API_KEY` in the `x-goog-api-key` header. No key occurs in a query, body, command argument, receipt or log.

1. One POST to `https://generativelanguage.googleapis.com/upload/v1beta/files`:

Headers:
- `Content-Type: application/json`
- `X-Goog-Upload-Protocol: resumable`
- `X-Goog-Upload-Command: start`
- `X-Goog-Upload-Header-Content-Length: <exact byte count>`
- `X-Goog-Upload-Header-Content-Type: video/mp4`
- `x-goog-api-key: <environment value, never logged>`

Exact body bytes:

```json
{"file":{"displayName":"c01.mp4"}}
```

2. One POST to the returned `X-Goog-Upload-URL`, only if it has exactly HTTPS origin `generativelanguage.googleapis.com`, path `/upload/v1beta/files`, one restricted `upload_id`, and optional `upload_protocol=resumable`. All other origins, credentials, fragments and query names are rejected before bytes or key are sent.

Headers:
- `Content-Type: video/mp4`
- `Content-Length: <exact byte count>`
- `X-Goog-Upload-Offset: 0`
- `X-Goog-Upload-Command: upload, finalize`
- `x-goog-api-key: <environment value, never logged>`

Body: exactly the verified MP4 bytes, read once into bounded memory. No metadata or answer text is appended. The session URL is held only in memory and never included in evidence.

3. If the returned file is `PROCESSING`, wait 5 seconds and GET `https://generativelanguage.googleapis.com/v1beta/files/<validated-id>`, with only authentication header and no body. Continue for at most 120 seconds total; a Linux wall-clock alarm includes socket time. At most 24 metadata requests are possible; the normal zero-latency synthetic deadline test makes 23. Already-`ACTIVE` uploads require no additional GET. Unknown states, `FAILED`, HTTP errors, malformed responses and timeouts stop immediately. No transport request is retried.

Success requires remote hash, bytes and MIME to match exactly; duration must be 6 seconds within 0.034 seconds (approximately one source frame, disclosed rather than called byte-/sample-exact timing). Resource URI must match the validated Google file name exactly.

For a possible later, separately reviewed token-count request, the official body shape would be:

```json
{"contents":[{"role":"user","parts":[{"fileData":{"mimeType":"video/mp4","fileUri":"https://generativelanguage.googleapis.com/v1beta/files/<validated-id>"}}]}]}
```

The endpoint would be `POST https://generativelanguage.googleapis.com/v1beta/models/<separately-verified-model>:countTokens`. This example is documentation only and cannot be reached by this probe. No `generateContentRequest`, prompt, model output, inference or tokenization is performed here.

## Workflow and failure behavior

- Manual-only `workflow_dispatch`, private exact repository, main ref, run number 1 and attempt 1; Python rechecks the boundary including workflow identity.
- Standard `ubuntu-24.04`, five-minute job ceiling, `contents: read`, checkout without persisted credentials. Shared existing evidence concurrency group prevents overlapping work.
- Existing runner python/ffmpeg/ffprobe must be present. No package install, billing change or environment setup is attempted. Missing tools fail before the secret-bearing step.
- Offline unit tests run first; the single control is generated and actually decoded/verified second; only the third phase receives the existing secret. Max media size 256 KiB, response size 64 KiB.
- One start and one bytes finalize call, with no automatic retry or paid fallback. HTTP redirects and environment proxies are disabled. No list, delete, model, external URL, upload retry or alternate-provider route exists.
- An exclusive local attempt claim is written before network activity. Receipt checkpoints precede effects. Existing claims/receipts block another process; reruns/new workflow runs are also blocked by run/attempt guards. A timeout or ambiguous response stays unresolved and must not be repeated blindly.
- Errors record only bounded internal codes such as `HTTP_403` or `REMOTE_HASH_MISMATCH`. No raw provider error, header, API key, session capability, response JSON or stack trace is intentionally logged.
- If byte finalization created a file but later validation fails, it is left to the provider's 48-hour expiry. No permanent delete is performed. No understanding/quality gate is promoted.
- Private artifacts contain text-only preflight, receipt, claim and local manifest/hash records. They deliberately exclude the MP4 and upload session URL. The Google endpoint never receives those operator artifacts.
